Read the whole group. Stamp only what’s real.

Partner WhatsApp groups bury a few real requests, and now and then a fake bank-detail change, under dozens of good-mornings.

The Triage Desk pulls out each request, checks the sender against the roster and stamps what may happen next. It executes nothing.

Two chats from the dev set, run through the real pipeline. Scroll, and each stage happens on the desk.

How it works

  1. The model describes. A free LLM reads the chat and lists each request: what is asked, which messages show it, what a follow-up refers to.
  2. Code decides who. The sender is looked up by phone in the roster. Claims and vouching in the chat never count.
  3. Code decides what. Ten written rules are all checked; the most cautious match wins, and the action is only logged.

              What these numbers do not show

              • The 15 dev chats were written by the same session that wrote the prompt, so these scores are optimistic and say little about new chats.
              • There is no baseline: nothing measures how much code-side grading beats one prompt that also grades.
              • The two challenge chats (the mandated scenarios) were generated by the same agent that built the system, so they are not an independent test. In v1.0 scenario 2 passed and scenario 1 failed; the two fixes were built on the dev chats only, and the challenge was then run once more, so it is no longer a blind test. Both scenarios now pass exactly.
              • The slot-time fallback and the explicit-ask check were tuned on these same dev chats, so the perfect grade and rule scores are fitted, not measured on new chats.
              • The 10 red-team chats were written by the same agent that built the system, and run once. The model flagged an injection only when it sat in the same message as the ask (1 of 4); in the other three, code still held the grade (hand-off or approval) because of risk or authority, not because of the flag.
              • The free model still leaves slot day and time empty; code now reads them from the message with a small Telugu word map and dateparser, and leaves them empty (ask approval) whenever the reading is not unique.
